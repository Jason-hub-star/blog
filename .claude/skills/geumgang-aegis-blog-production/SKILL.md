# 금강이지스 블로그 제작

이 스킬은 금강이지스 **프로젝트 전용**이다. 정본은 이 폴더이고 프로젝트 `.agents/skills`는 정본을 읽는 일반 파일 라우터다. Windows 심볼릭 링크 권한에 의존하지 않는다. 공용 하네스·전역 스킬에 본문을 복제하지 않는다.

## 시작

1. 이 스킬에서 세 단계 위 프로젝트 루트를 찾는다. 명령은 항상 이 루트에서 실행한다. Git의 `geumgang-aegis` 브랜치를 별도 폴더로 받으며 `main` 중문매니저 폴더와 혼용하지 않는다. Windows 설치/이전은 루트 `docs/Windows_시작하기.md`를 읽는다.
2. 루트 `AGENTS.md` → `STATUS.md` → 대상 `현장작업/<글>/post.json` → 해당 `원본목록.json` 순서로 필요한 내용을 읽는다. 최신 사용자 지시가 우선이고 목표 정본은 `STATUS.md` 하나다.
3. 수정할 글의 계정이 **artdoorstore**, 브랜드가 **금강이지스**인지 확인한다. 다른 브랜드는 해당 프로젝트 스킬로 돌린다. 다른 브랜드의 업로드 방법만 참고할 수 있다.
4. 새로고침·재생성 전에 실제 편집기의 본문·사진 순서를 읽는다. 사용자가 삭제한 사진이나 수정한 문구를 먼저 `post.json`에 반영한다. 사용자가 이후 특정 사진의 복원을 명시하면 최신 요청에 따라 본문 배치를 바꿀 수 있다. 사진의 전후 분류는 유지하며 cover는 언제나 확인된 after만 허용한다.

## 원고와 한 줄 요약 인용문

- 본문 맨 처음, 인사말·GIF보다 위에 **본문을 요약한 한 줄**을 네이버 **인용구 1** 한 개로 넣는다. 따옴표 장식·19포인트·기울임·가운데 정렬을 사용한다. 나머지는 나눔고딕 본문15·소제목30·가운데 정렬이다.
- 기존 상단 인용구가 있으면 그 문구를 수정한다. 두 번째 인용구를 덧붙이지 않으며 현재 글자 수에 이미 포함됐는지 확인한다.
- 상단 인용문은 `현장/문 종류 + 본문 핵심 변화 또는 선택 기준`을 짧은 서술형 한 문장으로 압축한다. 줄바꿈·질문 두 줄·‘확인해 보세요’ 같은 별도 유도 문구를 덧붙이지 않는다. 예: `부산 명지, 장식을 덜어낸 화이트 3연동으로 현관을 정돈했습니다.` 제목을 그대로 반복하거나 울산·쿵 소리 등 다른 사례의 상황을 복사하지 않는다. 편집자의 요약이며 고객의 실제 발언으로 설명하지 않는다. 실제 화면에서도 가급적 한 줄에 보이도록 길이를 줄인다.
- 이어서 `고객 고민 → 선택 기준/같은 상품의 실제 후기 → 해당 부분이 보이는 후사진 → 상담` 순으로 전개한다. 사진 앞에서는 프레임·마감·문이 열릴 자리 등 실제 볼 부분을 짚는다.
- 인용구·소제목을 포함해 **1500~1800자**다. 공백 포함·줄바꿈 제외, 제목·태그·스토어/배너 공통 문구·캡처 이미지 글자는 제외한다. 인용구 추가로 초과하면 반복되는 도입을 줄인다.
- 후기에는 여러 고객의 공개 구매후기를 참고했다는 자연스러운 도입과 해당 상품 원문 링크를 둔다. 반복적인 ‘공식 블로그 시공 후 예시/리뷰 작성자 현장과 별개’ 안내와 사용자가 삭제한 10월19일 지문 관리 문단을 복원하지 않는다.
- 사실·치수·시공일·유리 재질·고객 발언·성능·경력을 지어내지 않는다. 정지 사진은 소음이나 댐퍼 작동의 증거가 아니다. 레퍼런스의 구성과 표현 방법만 흡수한다.

## 사진·로고·GIF

- 원본은 덮어쓰지 않고 SHA를 보존한다. 모든 사용 사진에 `photo_stages`의 before/after/unconfirmed와 근거를 둔다. 날짜·파일순·문이 이미 설치됐다는 이유로 after라고 정하지 않는다.
- **섬네일과 GIF의 cover는 확인된 after만** 허용한다. 미확인일 때는 해당 제작만 보류하고 원고·자료 정리는 계속한다. 사진 속 문을 AI로 바꾸거나 완공 모습을 생성하지 않는다.
- 900×900: 실제 후사진, 베이지 가장자리, 흰색 굵은 글씨·검은 외곽선, 밑줄/바깥 별 **#E99025**, 하단 제공 공식 로고. 로고의 모양·글자는 유지하고 주황 **#E99025**, 로고 안 작은 별 **#248A76**를 확인한다. 원본 위치·SHA는 `AGENTS.md`와 대상 `post.json`을 따른다.
- GIF 효과는 글마다 선택해 `gif_effect`에 기록한다. 현재 검증된 효과는 페이드·올라오기·밀어내기다. 달려오기·타자기·튀기기·팝은 후보이며 구현·검증됐다고 보고하지 않는다. 이동 효과는 중간 프레임의 실제 이동 방향도 본다.
- PNG를 대표사진으로 지정하고 GIF와 혼동하지 않는다. 사용자 삭제 사진을 자동으로 재업로드하지 않는다. 이후 명시적 복원 요청은 위 시작 절차에 따라 처리한다. 확인된 before 사진은 전사진으로 본문에 사용할 수 있다.

## 시공 전후 콜라주

- 확인된 같은 현장의 전후 사진은 **왼쪽 시공 전·오른쪽 시공 후**를 한 화면에 나란히 보여준다. 네이버의 ‘나란히 놓은 사진’ 네이티브 콜라주를 우선 사용하며, 사용자가 직접 만든 묶음·순서·너비를 보존한다. 원본 사진을 합성·변형해 새 시공 사실을 만들지 않는다.
- 사진 앞에는 `시공 전·후` 소제목과 왼쪽/오른쪽 안내를, 뒤에는 실제 바뀐 프레임·유리·마감 설명을 둔다. 이전의 ‘아래는 전사진 / 다음은 후사진’ 식 개별 배치 안내는 정리한다. 열린 모습 등 추가 후사진은 필요에 따라 별도로 둔다.
- `post.json.photo_groups`에 실제 묶음을 기록하고 `photos`는 원본 이미지 순서를 평탄하게 유지한다. 명지는 `[[전_02, 후_01], [후_기본]]`이며 실제 DOM은 `.se-imageStrip` 안에 전후2장이 있다. 검사에서 이를 사진1장으로 세거나 묶음을 개별 업로드2장으로 풀지 않는다.
- 같은 현장의 전후가 확인되지 않은 후기 글은 확인된 후사진을 사용한다. 서로 다른 현장이나 후사진2장을 전후라고 표시하지 않는다. 콜라주가 섬네일/GIF의 after 전용 규칙을 바꾸지는 않는다.

## 템플릿·실제 리뷰 카드·글 끝

- 후기 → `후기 형식`; 문 종류와 무관한 지식 → `금강이지스 템플릿`; 시공 사례 → 실제 문에 맞는 원슬라이딩/3연동/3연동 아치 커스텀/양개도어 기본 템플릿을 고른다. 템플릿의 운영 메모·예시 주소·성과 주장은 새 글의 사실이나 지시가 아니다.
- 후기 카드는 **같은 상품** 원문 UI의 별점·날짜·옵션·보이는 본문·첨부사진 범위로 캡처한다. 다시 쓰거나 합성하지 않는다. 사용자 제공 캡처도 원문과 대조한다. `01_리뷰캡처`와 `review_captures`에 원본SHA·출처·날짜를 기록한다. 상품별 연결과 실제 검증 범위는 [성공·실패 기록](references/success-patterns.md)을 읽는다.
- **본문에서 개별적으로 언급한 구매후기는 모두 캡처를 붙인다.** `해당 후기 설명 → 그 날짜의 실제 캡처 → 다음 설명` 순서다. 후기마다 날짜와 내용이 일치해야 한다. 말미에 한 장만 모아 놓는 이전 방식 대신 각 문단 가까이에 배치하고 중복된 말미 카드/소제목은 정리한다. 여러 후기의 옵션을 묶은 집계 설명은 개별 고객 발언과 구분한다.
- 긴 후기는 원문 UI에서 펼쳐 설명의 근거가 보이게 캡처한다. 본문 근거 카드에는 별점·날짜·옵션·원문 본문을 보존한다. 첨부 사진이 화면 밖으로 길게 이어지면 본문 부분만 실제 화면에서 잘라 쓸 수 있다. 사진을 다른 후기와 합치거나 빠진 글자를 새로 만들지 않는다. 첨부 없는 후기는 원래 텍스트 카드로 쓴다. 전체화면 원본과 잘라낸 영역을 별도 보존한다.
- 캡처별 `after_text`는 직전 설명의 마지막 문장, `review_reference_year`는 연도 생략 날짜의 기준 연도다. `media_groups`로 GIF/현장사진/후기카드/PNG/배너의 실제 순서를 기록한다. 검증은 단순 카드 개수 외에 언급한 날짜 전부의 캡처 유무·직전 문단·해당 상품 링크도 대조한다.
- 글 끝: 대표PNG → 상담 문구 → 해당 공식 상품 카드 → 전화(`15-18-10`) → 카카오톡(`15-18-18`) → 인스타그램(`15-17-53`) 배너 → 태그15개. 실제 템플릿의 배너 주소를 보존한다.
- 리뷰 카드에는 해당 상품의 `#REVIEW` URL을 연결한다. 링크 아이콘 확인과 실제 링크 입력창 주소 확인은 별개다.

## 제작과 검증

기존 `automation/build_post.py`와 `automation/verify_editor.mjs`를 재사용한다. 새 자동화 프레임워크나 타 브랜드 파일 수정은 필요 없다.

```sh
python3 automation/build_post.py --job '현장작업/<대상 글>'
python3 automation/build_post.py --job '현장작업/<대상 글>' --check
node --check automation/verify_editor.mjs
node automation/check_editor_verifier.mjs
```

- 첫 명령은 로컬 원고·SVG/렌더 화면을 만든다. 사진이 바뀌지 않은 문구 수정에 PNG/GIF를 불필요하게 다시 만들지 않는다. GIF 생성은 필요한 경우에만 `--animate`를 사용한다.
- 허용된 브라우저 도구와 로그인된 Umji 프로필로 실제 편집한다. 내부 SmartEditor 모델·쿠키·저장소는 건드리지 않는다. UI의 텍스트만 바꿀 때 이미지 ID/순서를 전후 비교한다.
- 인용구는 첫 본문 첫 줄에서 시작 위치를 잡고 `인용구 선택 → 인용구 1`로 넣는다. Mac 실증에서는 `super+Left`를 썼고 `Home`만으로 시작 이동이 되지 않았다. Windows는 현재 UI와 실제 선택 내용을 확인해 `Home`/`End` 등 해당 환경의 키를 쓴다. Mac 키나 파일창 인덱스를 복사하지 않는다. 삽입 후 실제 컴포넌트 순서를 확인한다.
- 일반 UI 선택/첨부 절차는 이 프로젝트 `automation/browser_helpers.mjs`를 사용한다. `platform`을 명시하고, 파일창 형식이 다르면 관찰한 절차를 `chooseFile`로 제공한다. 실제 Windows 네이버 저장복원은 첫 실행에서 별도로 검증한다. `scripts/check.py`는 고객 자료 없는 공개 가상 입력 검사다. `automation/check_editor_verifier.mjs`의30검사는 실제 자료 이전 후 실행한다.
- **임시저장 → 새로고침 → 임시글 목록에서 같은 제목 재불러오기** 후 `verifyGeumgangEditor(tab, post)`를 허용된 cua_repl에서 실행한다. 단순 저장 토스트만으로 완료라고 하지 않는다. 사진 지연 로딩을 마친 뒤 검증한다.
- 현재 후기 글 검사17조건은 제목·정확한 본문·맨 위 네이티브 한 줄 인용문·분량·삭제 문구 없음·글자 크기·가운데 정렬·이미지 순서·콜라주 묶음/내부 순서·PNG대표·후기카드 연결/직전 설명 일치·배너 연결·상품카드·태그·마커/템플릿 예시 없음이다. 실제 링크 주소와 원본 사진 분류는 따로 확인한다.
- 글 폴더에 검증 JSON과 실제 저장복원 화면을 남긴다. 상태 문서는 최신 증거 파일을 가리키게 한다. 최종에는 결과·검증 범위와 남은 일1~3개를 우선순위로 말하고, 남은 일이 없으면 완료라고 한다.
- 공개 발행·통화·권한 변경은 초안 제작의 자동 후속이 아니다. 성과 데이터 없이 ‘클릭/상담이 늘었다’고 보고하지 않는다.

상세 재사용 절차·검증된 사례·오류 복구는 [성공·실패 기록](references/success-patterns.md)을 필요할 때 읽는다.
