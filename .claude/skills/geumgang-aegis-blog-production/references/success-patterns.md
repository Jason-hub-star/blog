## 편집기에서 검증한 실패 방지

- 상단 인용구를 추가하면 이전 `.se-text` 전용 검사에서 누락될 수 있다. `verify_editor.mjs`는 `.se-quotation .se-quote`도 문서 순서로 읽으며, 편집기 자리표시자인 ‘출처 입력’은 실제 본문에서 제외한다. 첫 인용구·한 줄·텍스트·스타일·19포인트·분량을 함께 검사한다.
- macOS에서 `Home`만으로 첫 줄 처음을 보장하지 못해 글자를 중간에서 나눈 사례가 있었다. 즉시 실행취소하고 `super+Left` 후 삽입했으며 실제 본문 일치와 이미지 순서를 재검사했다.
- 본문 선택은 복사한 내용이 기대 문단 전체와 일치하는지 대조한 뒤 붙인다. 클릭은 커서가 아니라 컴포넌트만 선택할 수 있다. 텍스트 수정 전후 이미지 ID를 비교한다.
- native 링크는 DOM `<a>`로 보이지 않을 수 있다. 이미지/텍스트 선택 → `링크 입력 열기`의 실제 입력창 값을 대조한다. 전화·카카오·인스타 주소는 `post.json.banners`/해당 글 링크 검증 증거가 정본이다.
- 파일 업로드 전에 실제 Chrome 탭을 활성화하고 절대 경로를 선택한다. 다른 글도 `대표사진.png`라는 같은 이름이므로 현재 폴더의 동일 이름을 근거로 고르지 않는다.
- 바이너리 PNG를 대용량 클립보드로 전달하지 않는다. 실제 파일 업로드를 쓴다. Cua 문서에 없는 API·내부 모델 조작을 쓰지 않는다.
- 팝업 리뷰의 `screenshot({clip})`이 underlying 페이지를 캡처한 사례가 있었다. 실제 보이는 `getScreenshot()` 원본을 보존하고 그 카드 영역만 잘라 사용했다. 텍스트·별점·옵션을 편집하지 않는다.
- 임시저장 후 새로고침의 ‘작성 중인 글’은 로컬 이어쓰기 여부다. 저장 완료를 확인한 다음 임시글 목록에서 정확한 제목을 골라 복원한다. 이름이 `임시저장된 글 보기, 10개`처럼 수량을 포함하므로 접근성 이름은 정규식으로 찾는다.

## 검사와 범위

- `build_post.py --check`: 원본/로고SHA·확인된 after cover·제외사진·상단인용구·본문1500~1800·삭제문구·색2·900²PNG·태그15·배너순서·GIF프레임/재생시간. 올라오기/밀어내기는 이동 방향도 확인한다.
- GIF의 팔레트 생성 전5초trim을 두어 잘못된2프레임140ms를 막았다. 실제3편은75프레임/5000ms다. 확장자만으로 움직임 성공이라고 하지 않는다.
- `check_editor_verifier.mjs`: 실제 저장DOM3편과 인용문/콜라주/본문/후기 문단·캡처/원문링크 변형30검사를 통과했다. 새 브라우저 저장복원의 대체물은 아니다. `build_post.py --check`는 개별 후기 날짜 전체와 캡처 날짜 집합·직전 설명도 비교한다. 후기 누락/문단 불일치 거절은 루트 `후기별캡처_제작검증.json`에 있다.
- 실제 새 글에서 추가 템플릿·새 효과·Windows를 썼다면 각각 새로 검증한다. Figma는 제공 보드에서 금강이지스 전용 영역만 편집한다. 다른 브랜드 노드·원본을 건드리지 않는다.
- 공개 발행·실제 문의 증가·모든 템플릿 신규 적용·후보7효과 구현은 현재 검증 범위 밖이다.


## Windows 이전에서 재사용할 경로

- Git은 금강이지스 `geumgang-aegis`, 중문매니저 `main`을 별도 clone 폴더로 유지한다. 같은 프로젝트의 Codex 일반 파일 라우터가 Claude 정본을 읽으므로 Windows 심볼릭 링크 권한이 필요 없다.
- 루트 `docs/Windows_시작하기.md`를 따른다. `scripts/check.py`는 실제 고객 자료 없이 동봉 폰트·UTF-8/BOM·한글/공백 경로·GIF3효과·편집기 계약을 검사한다. 실제 자료 ZIP을 복원하면 기존3편의 `--check`와 `check_editor_verifier.mjs`도 실행한다.
- 합성 입력과 파일창 모의 검사는 Windows 로그인 Chrome의 실제 첨부·저장복원 증거를 대체하지 않는다. 첫 실제 작업에서 현재 UI를 읽고 검증한다.
