# 프로젝트 목표와 상태

목표 정본: 이 문서. 중문매니저의 한 현장 블로그 제작을 재사용하고 전체60분을10분으로 줄일 수 있는지 실제 실행으로 검증한다.

- 최신 승인: 사용자가 줄인 세 간격을 보존해 스킬을 갱신하고 배너 아래 태그15개를 배치한다. 아내분이 사진5~10장으로 이어받을 현장 폴더·안내를 준비하고 /마감한다. 기존 Git 공유 승인도 유지한다. 공개 저장소에는 고객 사진/개인 문서/인증정보를 넣지 않는다.
- 원래 승인: 원본 구조 보존 수치 보정·로고·PNG/GIF·모바일 원고·초안 편집/임시저장·성공패턴 기록. 발행/통화는 자동 후속이 아니다.
- 현재: 상대경로·동봉 폰트·UTF-8/BOM·JPG/PNG·OS별 복사/파일창 처리를 GitHub에 공유했다. Mac 초안의 세 간격·배너 아래 태그15개를 저장복원16조건으로 확인했다. 현장별 폴더 생성과 아내분 안내를 추가했다.
- 완료 증거: 원본7장 불변,PNG/GIF 포함9개 미디어 바이트 동일,본문1800자,태그15개,사용자 간격/기존 사진ID 보존,새 clone 검사,Windows/Linux CI(최신 코드0f20aa8 모두 성공). 원격 검사 링크는 evidence에 기록했다. 실제 Windows 네이버 파일창·저장복원은 별도 실기 판정이다.
- 다음: 아내분이 [시작 안내](아내_시작하기.md)대로 새 현장5~10장과 현장메모를 준비한다. Windows 첫 현장의 업로드/저장복원과 전체 소요시간을 측정해10분 목표에 직접 기여한다.
- 의존성: Windows에 Git/Python과 실제 사진·배너를 준비한다. UI 자동화에는 해당 컴퓨터의 Chrome 세션과 허용 도구가 필요하다.
- 우회 복귀: 파일창 형식이 안 맞으면 로컬 산출물을 보존하고 현재 UI를 읽어 chooseFile을 제공하거나 허용된 GUI 도구로 첨부한다. 실패를 통과로 기록하지 않는다.
- 전체10분: 최초 조사·이식·CI 시간이 아니라 후속 현장 입력 준비부터 검수까지 별도 계측해야 한다.

- 2026-11-01 후속 승인/현재 위치: 사용자 ‘진행’ 지시에 따라 [공통 사진 접수 양식](../templates/blog-photo-intake/README.md)을 배포했다. 신규 사진은 `사진접수/현장`에 전·후·확인필요·영상·참고자료로 받고, 에이전트가 원본 상대경로→작업 사본/게시번호/대표 대응을 기록해 기존 제작 폴더로 연결한다. 기존 글과 제작 코드·서식·원본은 유지한다. 템플릿 동일성·로컬 게이트·새 clone 확인 후 main으로 공유한다. 다음 신규 현장과 Windows 실기/10분 계측의 의존성은 유지한다.
