# 프로젝트 목표와 상태

목표 정본: 이 문서. 중문매니저의 한 현장 블로그 제작을 재사용하고 전체60분을10분으로 줄일 수 있는지 실제 실행으로 검증한다.

- 최신 승인: 바탕화면 작업 폴더에 코드·스킬·하네스를 모으고 지정 GitHub 저장소로 공유해 Windows에서도 받아서 재사용한다. 공개 저장소에는 고객 사진/개인 문서/인증정보를 넣지 않는다.
- 원래 승인: 원본 구조 보존 수치 보정·로고·PNG/GIF·모바일 원고·초안 편집/임시저장·성공패턴 기록. 발행/통화는 자동 후속이 아니다.
- 현재: 상대경로·동봉 폰트·UTF-8/BOM·JPG/PNG·OS별 복사/파일창 처리로 이식 중. 기존 Mac 파일을 보존하고 실제 작업 설정은 post.local.json에 유지한다.
- 완료 증거: 원본 불변,7장 제작,PNG/GIF 일치,1800자,스킬 경로,새 clone 검사,Windows/Linux CI,원격 commit 일치. 실제 Windows 네이버 파일창·저장복원은 별도 실기 판정이다.
- 다음: 로컬/새 clone 검증→원격 공유→CI 확인. Windows 첫 현장에서는 로그인/브라우저 연결 후 임시저장→새로고침→불러오기 검사.
- 의존성: Windows에 Git/Python과 실제 사진·배너를 준비한다. UI 자동화에는 해당 컴퓨터의 Chrome 세션과 허용 도구가 필요하다.
- 우회 복귀: 파일창 형식이 안 맞으면 로컬 산출물을 보존하고 현재 UI를 읽어 chooseFile을 제공하거나 허용된 GUI 도구로 첨부한다. 실패를 통과로 기록하지 않는다.
- 전체10분: 최초 조사·이식·CI 시간이 아니라 후속 현장 입력 준비부터 검수까지 별도 계측해야 한다.

기존 Mac 실증과 자료 평가는 [RESULTS.md](RESULTS.md). Windows 단계별 확인은 스킬의 references/windows.md.
