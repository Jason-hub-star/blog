# 사진을 받아 블로그 초안 만들기

한 현장에 폴더 하나를 씁니다. 사진5~10장과 확인된 현장 정보만 준비하면 Codex 또는 Claude가 나머지 작업을 이어받습니다.

## 처음 한 번

Windows에 Git, Python3.10 이상을 준비하고 [README](../README.md)의 설치 명령을 실행합니다. Codex/Claude에서 받은 `blog` 폴더를 작업 폴더로 엽니다. Chrome은 중문매니저 네이버 계정으로 로그인하고 그 컴퓨터의 브라우저 제어 도구를 연결합니다. 로그인 정보는 Git에 넣지 않습니다.

기존 폴더를 받았다면 `git pull --ff-only`로 갱신합니다. Git에는 제작 도구와 스킬이 있습니다. 현장 사진·배너는 별도로 컴퓨터에 복사해야 합니다.

## 사장님에게 사진을 받으면

1. [공통 빈 양식](../templates/blog-photo-intake/README.md)의 `새현장` 폴더를 프로젝트 `사진접수` 안에 복사합니다. 이 Mac에 준비된 `사진접수/사진수신_대기`도 사용할 수 있습니다. 한 현장에 하나만 쓰고 이름은 `수신일_지역_현장별칭_문종류`로 정합니다.
2. 받은 원본을 **01_시공전 / 02_시공후 / 03_확인필요 / 04_영상 / 05_참고자료**로 나눕니다. 전후를 모르면 확인필요에 넣습니다. 원래 파일명은 유지하고 배너·다른 현장 참고·리뷰 화면은 참고자료에 둡니다.
3. 접수 폴더의 **현장메모.txt**에 지역/아파트, 제품·방식, 고객 고민, 선택 이유, 대표 후보를 적습니다. 모르는 것은 `미확인`으로 둡니다. JSON과 사진목록의 지문은 에이전트가 작성합니다.
4. 에이전트가 사진을 직접 보고 선별5~10장과 원본→사본/게시번호/대표 대응을 확인합니다. `new_job.py`로 제작 폴더를 만들고 선별 사본을 제작 **01_원본사진**에 복사합니다. HEIC 등은 원본을 유지하고 지원 형식의 사본을 만듭니다. 영상을 사진 제작 폴더에 넣지 않습니다.
5. 아래 요청을 보냅니다. 결과는 제작 폴더의 **03_작업결과**에 모입니다. 배너는 제작 **02_참고자료** 또는 네이버 ‘내 템플릿’으로 연결합니다. 원본 접수 폴더와 기존 현장은 이동하지 않습니다.

> 공통 사진 분리 가이드와 AGENTS.md를 읽고 [접수 폴더]의 사진·메모를 확인해줘. 사진목록에 전후 근거·작업사본명·게시순서·대표를 기록하고, jungmun-blog-production 스킬의 기존 제작 폴더로 연결해 이번 현장 글을 만들어줘. 기존 사용자 수정을 보존하고, 확인한 사실로 1800자 본문·짧은 제목·집 모양 PNG와 순차 GIF·보정사진을 만들어줘. 사진 수와 본문 배치를 맞추고 확인된 후사진 PNG를 대표로 선택해줘. 소제목30굵게/본문16, 세 군데 간격, 하단 배너 뒤 태그15개를 적용해 임시저장하고 새로 열어 검증해줘. 공개 발행은 검토 후 내가 할게.

```text
현장작업/
  YYYY-MM-DD_지역_아파트명/
    01_원본사진/       ← 에이전트가 접수 원본에서 확인·복사한 선별5~10장
    02_참고자료/       ← 배너·참고 디자인
    03_작업결과/       ← 보정사진·PNG·GIF·원고·검증
    현장메모.txt       ← 확인된 사실
    시작하기.txt
    post.local.json    ← 에이전트가 관리하는 이 현장 설정
```

제작할 때 파일명순으로 photo_001부터 번호가 붙습니다. 사진을 추가·삭제·이름 변경한 뒤에는 에이전트에게 사진 번호/배치/대표사진을 다시 맞춰 달라고 합니다. 기존 현장 폴더는 덮어쓰지 않습니다. 같은 날 두 번째 작업이면 현장명 끝에 `_2`를 붙입니다.

## 직접 명령을 실행할 때

Windows PowerShell, 저장소 루트에서:

```powershell
py -3 scripts/new_job.py "지역_아파트명"
# 사진이 이미 한 폴더에 모였다면 위 명령 대신 다음 명령으로 복사까지 합니다.
py -3 scripts/new_job.py "지역_아파트명" --photos-dir "C:\받은사진\현장"
```

새 설정은 `needs_authoring:true`로 잠깁니다. 사진·메모로 제목/본문/제품/태그/상담 링크를 검토한 후에만 에이전트가 false로 바꾸고 생성합니다. 사진이 없는 상태에서 만든 폴더는 사진을 넣은 뒤 실제 장수에 맞게 이미지 블록을 조정해야 합니다.

사진이 다른 드라이브에 있어도 `--photos-dir`로 복사할 수 있습니다. 별도 `--config`를 사용할 때 폰트는 저장소 안의 동봉 폰트를 가리켜야 합니다. 다른 드라이브의 폰트나 없는 폰트는 폴더를 만들기 전에 거절합니다.

```powershell
.venv\Scripts\python.exe automation/build_assets.py --config "현장작업\YYYY-MM-DD_지역_아파트명\post.local.json"
.venv\Scripts\python.exe scripts/check.py
```

Mac에서는 `py -3`를 `python3`, `.venv\Scripts\python.exe`를 `.venv/bin/python`으로 바꿉니다.

## 마지막 확인과 인계

- 본문1800자는 공백·소제목을 포함하고 제목·줄바꿈·사진 속 글자·태그는 제외합니다. 일반 문장 뒤에는 빈 문단 하나를 둡니다.
- 제목과 첫PNG 사이에 빈 텍스트를 넣지 않습니다. `안녕하세요.` 다음 문단에 **중문매니저**입니다.를 붙이고, 마지막 문장과 배너 사이 빈 문단은 최대 하나로 둡니다.
- 배치는 본문→상담배너→태그15개입니다. 태그는 이번 현장의 지역/아파트/확인된 문 종류와 관련된 단어를 고릅니다. 순위나 검색량을 보장하지 않습니다.
- 본문 해시태그와 네이버 발행 설정의 등록 태그는 별개입니다. 공개 발행을 결정했을 때 등록 태그에도 같은15개를 입력합니다.
- 저장→새로고침→임시글 불러오기 후 사진·PNG대표·GIF·서식·태그를 확인합니다. Windows 실제 네이버 조작은 첫 현장에서 검증해야 합니다. 자동 검사는 로그인된 편집기 실기를 대신하지 않습니다.
- 다른 컴퓨터에서 현재 현장을 이어가려면 해당 현장 폴더를 별도로 전달합니다. 폰트 경로는 저장소 기준 상대경로입니다. 사진/배너/계정정보는 공개 GitHub에 올리지 않습니다.

현재 산들마을아파트 초안은 네이버 임시저장 목록의 **성남 아파트 중문, 답답함 없이 깔끔한 현관 만드는 법**으로 열 수 있습니다. 같은 계정으로 접속해 이어받고, 새 현장 글과 혼동하지 않습니다. 전체60분→10분 목표는 다음 실제 현장 시작부터 저장 검수까지 시간을 재서 확인합니다.
