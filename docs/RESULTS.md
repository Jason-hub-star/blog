## 기존 Mac 실증 — 2026-11-01

- 한국어 Chrome Umji의 중문매니저 한 현장에서 사진7장 수치 보정, 집 모양1080 PNG/GIF, 갈색 명조 브랜드,본문1800자를 생성했다.
- 소제목30굵게·본문16·선택 단어 굵기·문장 뒤 빈문단·PNG단독대표·하단배너를 실제 편집기에서 대조했다. 임시저장→새로고침→불러오기12조건 PASS.
- 확장 파일 첨부 권한 제한은 네이티브 파일선택으로 해결했다. 사진 교체 후 PNG대표를 재지정했다. 화면 밖 GIF 미로딩을 유실로 오판하지 않았다.
- 사용자 수동 제목은 로컬 설정에 동기화하고 다시 덮어쓰지 않았다.
- 스킬 형식·발견 링크·별도 임시 폴더 재생성 PASS. Windows 실제 네이버 UI·공개발행·실제폰·전체10분은 이 Mac 증거로 판정하지 않았다.

## 제목·외부 자료

숫자 제목이 검색 순위를 높인다는 공식 공개 근거를 확인하지 못했다. 자료19장의 고객 질문 도입·현장 원자료 입력은 편집 아이디어로 평가했고, 반복5~7회/15회 제한·사진5장·1800~2000자·추천/개선 수치·60개 주제/대량 발행을 필수 규칙으로 채택하지 않았다. 상세 근거는 스킬의 references/title-evidence.md.

- 기존 사진7장과 PNG/GIF를 새 제작 코드로 재생성한9개 미디어는 기존 결과와 바이트가 같고 원본은 불변이었다.
- 오프라인 키보드/대화상자 fixture 검사는 실제 Windows 네이버 UI 증거가 아니다. 로그인된 Windows의 업로드/저장복원·전체10분은 미검증이다.

## 간격·태그·아내분 인계

- 제목→첫PNG에 빈 텍스트 없음, 인사말 두 문단 사이 빈 문단 없음, 마지막 문장→배너 빈 문단1개인 사용자 수정을 확인하고 보존했다. 태그 추가 전후 기존 사진10개 컴포넌트ID와 기존 본문 문단(빈 문단 포함)은 같았다.
- 배너 아래 관련 태그15개를16/보통체/3개씩 넣었다. 본문1800자에서 태그를 제외해 검사 범위를 나눴다. 임시저장→새로고침→불러오기16조건 PASS. 본문 해시태그만 배치했고 발행 설정의 등록 태그는 입력하지 않았다.
- 현장별 원본/참고/결과 폴더, 사실 메모, 상대경로 설정을 만드는 CLI를 추가했다.5/10장 복사·원본 바이트 보존·무덮어쓰기·Windows 금지 이름·상대 배너경로·새 현장 작성 전 생성 차단을 검사했다.
